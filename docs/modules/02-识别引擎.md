# 模块讲解 02：识别引擎（Detection Engine）

> 对应代码：`cipherscope/core/detector.py`

---

## 一、原理篇

### 1.1 问题定义

攻击调度器不知道该调用哪个插件，评分引擎不知道该期待什么结果。**识别引擎的职责是回答"这段密文最可能是什么"**，输出按置信度降序的候选类型列表，调度器据此排序攻击。

### 1.2 三类检测信号

| 类别 | 依据 | 适用场景 |
|---|---|---|
| 模式匹配 | 字符集、长度特征、正则 | base 系、摩斯、Brainfuck、哈希——强特征，置信度高 |
| 文本统计 | 重合指数(IC)、Kasiski 检验 | 区分单表替换(凯撒/仿射)与多表替换(维吉尼亚) |
| 二进制分析 | 可打印比例、信息熵 | XOR 候选、真加密(AES 等)提示 |

### 1.3 重合指数（Index of Coincidence）

**定义**：从文本中随机抽两个字母，它们相同的概率。

```
IC = Σ cᵢ(cᵢ-1) / n(n-1)      cᵢ 为第 i 个字母出现次数
```

**为什么能区分密码类型**：
- 英文明文 IC ≈ 0.066——字母分布极不均匀（e 出现 12%）；
- **单表替换（凯撒/仿射/Atbash）不改变字母分布形状，只是平移** → IC 保持 ≈0.066；
- **多表替换（维吉尼亚）把不同移位混在一起** → 分布趋向均匀 → IC ≈ 0.0385；
- 随机文本 IC ≈ 0.0385。

所以：`IC ≥ 0.055 → 单表替换候选`；`IC ≤ 0.045 → 多表替换候选`。**这是识别引擎最有密码学含量的一步**。

### 1.4 Kasiski 检验

维吉尼亚的密钥周期会在密文中留下重复模式：明文相同片段被相同密钥段加密 → 密文相同片段。**统计重复片段间距的公约数，出现最多的就是密钥长度**。

### 1.5 信息熵

```
H = -Σ pᵢ·log₂(pᵢ)    单位: bits/byte
```

- 英文文本 ≈ 4.5；base64 ≈ 6；随机/真加密 ≈ 8。
- 熵 > 7.5 且不可打印比例高 → 提示"现代加密(AES)，超出古典攻击范围"，避免浪费时间。

## 二、开发中实际踩过的坑（已修复）

### 坑：可打印 ≠ 自然语言（XOR 检测盲区）

单字节 XOR 密钥落在 0x20~0x7F（可见字符区）时：
- 明文的**空格**(0x20) 被异或成可见字符（如 ^0x42 → 'b'）；
- 明文的**字母**被异或成标点（如 't'^0x42 → '6'）。

结果密文**全部可打印，但字母占比异常低**。初版识别引擎用"可打印比例 < 0.7"判定 XOR，这类密文被漏检。修复：新增分支——**文本可打印但字母占比 < 65% 且长度 ≥ 20 → XOR 候选**。这是 CTF 实战中最常见的 XOR 题形态。

## 三、代码走读

```
DetectionEngine.detect(data)
 ├─ _pattern_detections: 字符集/长度/正则强特征 (morse/brainfuck/hex/base系/hash)
 ├─ _text_detections:    字母流 IC 判定 + Kasiski 定钥长 (需样本 ≥20 字母)
 └─ _binary_detections:  可打印比例 + 熵 (XOR/强加密)
 └─ 按置信度降序排序返回
```

**关键实现点**：
- 统计工具（`shannon_entropy` / `index_of_coincidence` / `kasiski_key_lengths`）独立成模块函数，插件可复用；
- **短样本防护**：字母 < 20 时 IC 不可信，不产出文本类检测——把判断交给攻击插件的穷举 + 评分引擎（决策正确性 > 决策完整性的取舍）；
- base64 检测的**字符多样性条件**：纯 A/B 的培根密文也匹配 base64 字符集，需 `len(set) ≥ 8` 才给高置信——否则培根题会被 base64 插件抢先误解。

## 四、面试问答预演

**Q1：重合指数为什么能区分凯撒和维吉尼亚？**
A：凯撒是字母频率的循环平移，分布形状不变，IC 保持英文明文值 ≈0.066；维吉尼亚把多个移位叠加，每列分布被稀释，整体趋向均匀，IC 跌到 ≈0.0385。IC 是对"分布不均匀程度"的度量，所以能区分单表/多表。

**Q2：IC 的局限？**
A：样本太短时统计噪声大——20 字母以下的文本 IC 完全不可靠，所以引擎对小样本不做文本类判断。另外明文若是中文、数字串等非英文，IC 无意义。这是"识别引擎给出候选、评分引擎最终裁决"分工的原因之一。

**Q3：可打印的 XOR 密文怎么识别？**
A：密钥在可见字符区时密文全可打印，但字母占比骤降——空格被异或成可见字符、字母变标点。引擎加了"可打印但字母占比 <65%"的专用分支。这个盲区是真实踩坑发现的（详见上文）。

**Q4：识别错了怎么办？**
A：识别引擎只输出**候选列表 + 置信度**，调度器按置信度排序但**不排除低置信插件**（match>0 都会尝试）。识别错误最多导致攻击顺序不佳，不会漏掉正确路径——这也是插件架构容错性的来源。
