# 模块讲解 04：XOR 分析

> 对应代码：`cipherscope/plugins/xor_attack.py`

---

## 一、原理篇

### 1.1 为什么 XOR 是 CTF 高频题型

XOR 是位运算：`c = m ⊕ k`。它同时具备三个特性：**对称性**（`m = c ⊕ k`，解密即加密）、**位独立性**（逐字节处理）、**数学简单**（无进位/借位）。出题人爱用它，因为看起来"加密了"但其实只是掩码——CTF 入门题的经典送分题。

### 1.2 单字节 XOR

密钥 1 字节（256 种）。穷举全部密钥，每个候选交给评分引擎，**评分最高的就是明文**。注意 XOR 结果可能落入可打印区（见模块 02 的盲区修复），因此候选筛选不能只看可打印比例。

### 1.3 多字节 XOR（重复密钥）

密钥 k 字节，明文按 k 字节周期异或。两步破解（Cryptopals Set 1 标准方法）：

1. **定密钥长度**：相邻密钥周期的明文对应位置共享相同密钥字节，若 klen 猜对，`c[i] ⊕ c[i+klen] = m[i] ⊕ m[i+klen]`——密钥抵消，只剩明文字节差。英文明文在周期位置上的分布有规律（空格对齐时差为 0），**归一化汉明距离显著最小**：
   ```
   distance(klen) = mean( hamming(block_i, block_{i+1}) / klen )
   真实 klen 处距离最小
   ```
2. **按列定密钥字节**：把密文按列（`c[j], c[j+klen], c[j+2klen]...`）分组，每列是"单字节 XOR"——列内频率最高的字节假设为空格(0x20)异或后的值，密钥字节 = 该字节 ⊕ 0x20。

### 1.4 已知明文攻击（crib dragging）

知道明文片段（如 `flag{` 前缀）时：`key_fragment = c[0:len] ⊕ crib`。若密钥是单字节，fragment 全部相同；若是周期密钥且 fragment 够长，能还原整个周期。

## 二、开发中实际踩过的坑（重要）

### 坑：汉明距离法对重复性强的文本失效

初版用标准汉明距离定钥长，在真实语料上失败——测试明文 `FILLER` 含大量重复短语（"the secrecy of the key" 出现多次），**错误密钥长度下相邻块的明文距离也被压低**，区分度不足，keylen 猜错（3 猜成 8/15）。

**修复：空格启发法替代汉明距离作为主方法**。英文明文空格频率最高（15%+），所以密文每列出现频率最高的字节 = 空格 ⊕ 密钥字节 → `key_byte = mode(列) ⊕ 0x20`。对 2~16 全部候选长度做"恢复密钥→解码→评分"，取分数最高的前 2 个。实测在重复文本上鲁棒（密钥 "abc"/"s3cr3t" 均 100% 命中）。

**教训**：标准方法（Cryptopals 汉明距离）在理想均匀文本上成立，但真实语料可能破坏其前提。**攻击必须针对实际数据分布做鲁棒性设计，并用语料库实测验证**——这是"理论方法 vs 工程实践"的典型案例，也是面试时很出彩的谈资。

## 三、代码走读要点

- `XorSinglePlugin`：256 穷举后**内部先用评分引擎预筛 top-5**（避免 256 个候选淹没调度器）——插件内预筛 + 调度器统一裁决的两级结构；
- `XorMultiPlugin.attack`：空格启发法对 2..16 全跑 → 解码 → 评分 → top-2；
- `XorKnownPlaintextPlugin`：`flag{`/`ctf{`/`NSSCTF{` 三组 crib 自动尝试，单字节密钥（fragment 全同）与周期密钥（fragment 短周期）两条路径；
- 汉明距离实现保留为 `_guess_keylen` 备用（未来可做方法融合）。

## 四、面试问答预演

**Q1：多字节 XOR 的密钥长度怎么确定？**
A：标准方法是归一化汉明距离——密钥周期对齐时，相邻周期块的对应字节共享相同密钥位，异或后密钥抵消，只剩明文差；英文明文周期对齐时分布有规律，汉明距离显著小。但我实测发现重复性强的文本会破坏这个前提，所以最终主方法用了空格启发法（每列最高频字节 ⊕ 0x20 = 密钥字节），对 2~16 全长度尝试取评分最高者——对真实数据更鲁棒。

**Q2：为什么用空格假设？**
A：英文统计中空格出现频率最高（约 15%，远超 'e' 的 12%）。每列是明文按周期子采样，空格仍是列内最高频字节。XOR 是位运算，密文列内最高频字节 = 空格 ⊕ 密钥字节，异或回去即得密钥。假设成立的前提是明文英文含量高——CTF 解密目标就是英文 flag，前提自然满足。

**Q3：已知明文攻击怎么用？**
A：CTF 的 flag 格式是公开约定（`flag{`/`NSSCTF{`），把它当 crib：密文头部异或 crib 得密钥片段。单字节密钥时片段全同立即定钥；周期密钥且片段够长时能还原整个周期。这是"已知明文攻击"思想在 CTF 场景的直接应用。

**Q4：XOR 解密结果怎么判断成功？**
A：评分引擎多信号裁决（n-gram/词典/flag 格式），而不是可打印比例——因为 XOR 密文完全可能是可打印的（密钥落可见区），这个盲区是识别引擎的真实踩坑点。
