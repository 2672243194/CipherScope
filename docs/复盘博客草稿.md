## 一、为什么做

CTF 密码学题目千变万化，但解题链路高度重复：识别 → 攻击 → 验证。  
市面上工具各有缺口：CyberChef 手动、Ciphey 古典覆盖弱、RsaCtfTool 只有 RSA。  
**没有一个工具能把「识别 → 调度 → 攻击 → 评分 → 嵌套深挖」全链路自动化。**

## 二、架构决策（附理由）

1. **插件化攻击框架**：`match()`（轻量置信度）与 `attack()`（惰性候选）分离，调度器按置信度排序、评分超阈值即短路。第三方经 `entry_points` 可扩展——把"加一种攻击"从改代码降为写一个类。
2. **评分引擎是核心**：flag 正则 + n-gram 适应度 + 可打印比例 + 词典命中 + 卡方 + 中文兜底，六信号加权融合。三档裁决 SUCCESS/PROMISING/REJECT 服务于嵌套解码：中间层"像文本但没 flag"需继续深挖。
3. **编码链优先**：codec 确定性解码产物无条件进入下一层——多层 base64 套娃的中间层本就不像自然语言，按评分剪枝会截断整条链。

## 三、踩坑实录（最有价值的部分）

| 坑             | 现象               | 根因               | 修复                       |
| ------------- | ---------------- | ---------------- | ------------------------ |
| 稀疏 quadgram 表 | 评分信号整体归零         | 表覆盖率 <5%         | 兜底改 trigram + 覆盖率感知      |
| 信号权重失衡        | 最弱信号主导评分         | 权重不随表模式调整        | `_SIGNAL_WEIGHTS` 随模式自适应 |
| 可打印 XOR 密文漏检  | 密文全可打印被当明文       | 密钥落可见区，字母占比骤降    | "可打印但低字母占比"专用分支          |
| 假 flag 短路     | 乱码中碰巧含 flag{     | 长乱码概率 ~1/45 万/字节 | 长文本要求上下文 base 达标         |
| 汉明距离定钥失败      | XOR 多字节猜错钥长      | 重复文本破坏距离区分度      | 空格启发法（列 mode ⊕ 0x20）     |
| 键盘位移边界错位      | round-trip 失败    | 非双射映射            | 行内循环位移                   |
| 字符集包含误匹配      | base85 抢跑 base64 | b85 ⊇ b64 字符集    | 要求含 b64 外符号              |

## 四、数据说话

- 34 道自构造语料（全部插件正反路径 + 多层组合）**通过率 100%**；
- 49 个单元测试全绿；
- 单题求解时间 <0.3s（预算内短路）；
- 代码量约 1500 行（核心四件套 + 19 个插件 + Web）。

## 五、路线图

完整 quadgram 表调参 → 中文 n-gram 评分 → 真题语料扩至 100 题 + CI 通过率徽章 → PyPI 发布。
